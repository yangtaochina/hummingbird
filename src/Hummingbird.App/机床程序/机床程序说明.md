# 配套机床程序与上位机配置

这整个目录属于源码交付内容，编译后自动复制到程序目录的“机床程序”文件夹。日常操作不需要选择JSON，也不需要重新生成MPF。这里备份的是此前已经生成的现场程序，未修改运动逻辑、参数或通信会话。

| 文件 | 使用位置 | 用途 |
| --- | --- | --- |
| HM_RETURN.MPF | 机床面板 | 工位恢复程序；面板启动后先等待上位机请求 |
| 工位恢复配置.json | 上位机自动读取 | 恢复顺序、目标、入口范围、速度、R区及MZ2保持条件 |
| HM_MASTER.MPF | 机床面板 | 整件采图和18孔的连续XY调度主控；面板启动后等待上位机请求 |
| 整件加工配置.json | 上位机自动读取 | XY边界、固定Z/C、专用R区、会话161339及加工许可 |

JSON不用上传到机床。它们不包含连接密码，也不会自动修改激光工艺、连接设备、确认装夹、启动NC或出光。工艺时长／功率仍在第1页设置并读回核对。机床已有对应MPF时，直接选择已有程序使用；HM_MASTER_FIX或此前上传后的实际程序名可以沿用，前提是内容对应这份主控。

## 自动光学与落点校准（v1.5.0新增）

新增`HM_OPTICAL.MPF`与`自动光学校准配置.json`，自动读取本地参数，面板启动后等待上位机采样请求。与原主控使用相同已核定的XY包络和R220～229，但校准会话171501独立于整件主控161339，不能互相替代。程序不移动Z/C，也不含激光指令；上位机只有在用户确认本次留痕位置与参数后，才在XY完成并退出NC后调用一次原试打流程。

第5页现默认自动采图和计算，无需选择照片或JSON。具体顺序、失败处理及新流程实机边界见[自动光学校准操作.md](自动光学校准操作.md)。原HM_RETURN和HM_MASTER完全保持不变，机床已有对应程序无需因本次更新重传。

## 第2步：工位恢复

1. 结束其他NC，确认本次参考有效及回位区域、MZ2保持条件。
2. 机床已有对应HM_RETURN时，在面板选择该程序，从头Cycle Start一次。此时只进入等待，不立即回位。
3. 在上位机第2页勾选本次确认，点“开始恢复表盘工位（不出光）”。软件仍核对关光、实际入口、配置编号和完成快照；原有检查不变。
4. 完成后，切到第3页进行新件或已关联的同件补加工流程。

恢复顺序：MZ1=-192.17803 → C=254.8245° → X=-135.02745/Y=-188.57564 → MZ1=-201.87324mm；MZ2不动。原入口范围继续有效，不从任意位置盲目恢复。

## 第3步：定位与加工

1. 全新件建立新记录；同一已加工件从第4页准备关联的补加工／未出光重试记录。
2. 在机床面板选择已有的对应主控，从头Cycle Start一次，进入等待。同一轮已经处于等待时，不无缘由重复Cycle Start。
3. 上位机确认本次装夹、参考、固定C、主控和路径，检查整件就绪，再开始本轮加工。全部原有定位、读回、关光和防重复加工检查保留。

两份MPF共用已核定的R220～R229，不能同时运行。

## 机床没有对应程序时

在第2页或第3页点“前往上传”，会切换到“维护与辅助→NC文件”并预选对应的本地MPF。此步骤只切换界面；操作者在上传对话框确认后，才按原流程上传并回读。也可使用现场原有方法上传本目录里的MPF。

本软件为避免覆盖旧NC，会将上传文件命名为HM_CHECK_时间.MPF。上传并回读一致后，**在机床面板选择界面报告的实际名称**，不能仅按本地文件名寻找。上传不会自动启动机床。

## 配置维护

程序默认使用本目录的两份JSON。以前在维护入口指定的配置仍存在时优先保留；旧路径因复制程序或迁移电脑失效时，使用本目录备份。有效路径上的文件损坏时会提示未就绪，不静默切换到另一套配置。

第2页“配置说明／维护”及第3页“主控程序／配置说明”可以查看当前配置来源，必要时更换配置或重新导出。默认交付的JSON会与本目录对应MPF的生成内容核对；不一致时拒绝使用。配置确实改变后，须按维护流程核对新MPF，不能继续套用旧程序。
