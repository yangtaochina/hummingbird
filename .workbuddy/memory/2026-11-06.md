# 2026-11-06 工作日志

## 1. 客户新思路：用机床转台分度拍摄做定位（方案判断，暂未写码）

用户实测反馈：**相机根本拍不到大圆环上的 2 个甚至 3 个双环小圆**，
故上一轮的「多孔自主定位」策略④在现场行不通。
新提议：机床有转台，可用命令让它转动，让相机拍更多信息
（3 个圆、甚至整个表盘），再做定位打孔。问是否可行。

### 判断：可行，且是目前最根本的一条路
转台提供**精确已知的角度增量** = 免费的角向基准。
前面所有死结（找不到角向基准、8 孔 90° 对称消歧、两孔镜像二义性）全部消失。
多帧把「一帧看 3 孔」降成「一帧看 1 孔」，视野可缩小、放大倍数拉满。
把每帧孔心绕转台回转轴逆旋转 −φ 合并回基准系，即可**复用已验证的多孔求解器**。

### 但必须先澄清一个更基础的根因（重要）
用户「拍不到孔」可能根本不是照明问题，而是**孔在画面外**：
- 真机实测 mm/px ≈ 0.0234 → 视野 44.9 × 28.1mm，垂直半高 **14.0mm**
- 基准孔圈 R = **14.45mm** > 14.0mm → 孔圈刚好出画
- 相机目前对着工件中心，视野里本来就没有基准孔
⇒ 换白光也拍不到。转台转动本身**不能把画面外的孔变进画面**
  （若工件中心≈转台回转轴，孔只会绕中心转，半径不变，永远在框外）。

**最小动作**：先用工作台 XY 把视野中心移到孔圈上（偏移 14.45mm），
或把相机外移，让孔圈进入视野；拍一张确认孔成像，再谈转台。

### 三条硬约束（转台方案的风险点）
1. **最大风险：必须打通 828D 转台轴通讯**（下发角度 + 读回实际位置）。
   OPC UA 网络问题仍挂着（服务器在 PCU/IPC 的 X1，X130 改网段无效），
   用户当时暂停了机床网络。转台方案强依赖它，必须重新捡起来。
   还需确认：转台是否为数控轴（轴名）、角度精度、有无回程间隙。
2. **孔必须成像**：手机白光照片能看清小黑孔，相机红光图基准孔环带
   灰度标准差仅 4.9/255 → 换白光/蓝光 + 曝光 5000~8000μs、增益 0。
   转台解决「数量/视野」，不解决「对比度」。
3. **新增标定：工件中心相对转台回转轴的偏心**。照片显示托板随手摆放，
   工件明显不居中；转台转动时工件会绕回转轴公转。
   好处是多帧同一特征轨迹可拟合出回转中心（转台自标定，3 点定圆），
   偏心反而能被解出来；坏处是拼接前必须做偏心补偿，否则孔摊成一片。

### 更省事的工艺（比「拼图定位」更推荐）
不要拼整盘图，直接**分度打孔 + 局部视觉闭环**：
转台把每个待加工孔依次转到激光光斑/相机视野下 → 局部拍照测偏差 →
XY 补偿 → 打孔 → 下一个角度。18 次分度。
角向由转台保证，偏心由每孔实测吸收，视觉每帧只需看到 1 个特征。
需补标定：激光光斑 ↔ 相机视野中心偏置（九点标定本来就要做）。

### 现场 3 步判别（手工，不改代码）
1. 手机手电/白光照明，曝光 5000~8000μs、增益 0，拍一张。
2. 工作台 XY 移 14.45mm 让视野对准孔圈，再拍一张 —— 看孔在不在、清不清。
3. 手动把转台转 30°，再拍一张 —— 看孔是否换了一组、位置变化是否符合角度。
三张都合格 → 转台方案成立，可落地策略⑤。

### 本轮未写码的原因
策略⑤依赖「转台能通讯 + 孔能成像」两个未确认前提，
先写会在现场跑不起来、且可能方向错。等用户回传 3 张验证图后一次性落地：
`StrategyIds.RotaryScan` + `RotaryScanStrategy`（多帧逆旋转合并、
转台自标定拟合回转中心、复用多孔求解器）+ 界面采集按钮 + 合成图测试。

白光全黑 + 红光才有图像 ⇒ 相机前**很可能装了红色窄带滤光片**

- 想提高小孔对比度，只能改**红光照明方式**：同轴光 / 低角度斜照明 /
  偏振片 / 调整入射角让孔产生阴影，而不是换光源颜色

   程序照样能采多帧、后续逆旋转合并。**完全绕开还没打通的 OPC UA**。
自动分度（OpcUaRPlc）作为可选增强，等机床侧配合好再切。

  触发位必复位、完成信号残留检测

  西门子 OPC UA 官方手册列的方法只有：用户管理、文件传输、刀具管理、程序选择，

## 4. 现场 bug：曝光扫描把相机留在 1000000us 全白档（已修）

### 现象（用户回传）
pylon Viewer 里设 5000us，跑过我方软件后变成 **1000000.0**；
贴回的曝光扫描报告末尾还有「画面整体过曝（均值 255/255、标准差 0.0）全白一片」。
config.json 里确实是 5000 → 不是配置没读到。

### 根因（逐行核实，非猜测）
- `MainForm.cs` 诊断②扫描序列最后一档 = **1000000us**
- `BaslerCameraService.ScanExposureAsync` 每档直接 `SetExposureUsAsync(us)` 写相机寄存器
- **扫完没有恢复** → 相机停在 1000000us；紧接着点「③视野诊断」拍到的就是全白帧，
  关掉软件后 pylon Viewer 读到的也是这个残留值（相机参数不会随进程退出回滚）
- `OpenCamera()` 其实调用了 `ApplyConfiguredCameraParams()` 下发 5000，所以「打开」没问题，是扫描把它改坏了

### 顺带发现的三个不一致
1. 界面 `_numExp` 写死 8000us / 增益 1，配置是 5000us / 增益 0 → 点「应用参数」又改回 8000
2. `ApplyConfiguredCameraParams` 用 `if (CameraGain > 0)`，导致配置里的 **0 被当成「不设置」永不下发**
3. 扫描报告「更稳的一档」用 `OrderBy(MeanGray).First()` → 恒等于最短曝光档，两份推荐重复输出 5000

### 修复
- `BaslerCameraService.ScanExposureAsync`：扫描前读当前曝光，**finally 必恢复**（异常路径同样），日志打印恢复值
- `MainForm.DiagExposureScan`：catch 后加 **finally 双保险**，强制下发 config 值并同步界面控件；报告末尾追加「已恢复为配置值」一行；异常时提示手动点应用参数
- 构造函数把界面初值同步 config；`CameraGain >= 0` 恒下发（0 是合法值）
- 「更稳的一档」改取均值最接近 120 的档（新数据下 = 20000us / 均值 123.2）
- `AppConfig` 注释补 2026-11-06 复测数据：5000us 46.8 / 20000us 123.2 / 50000us 206.3 起过曝

### 验证与待现场核验
编译 0 错 0 警，SmokeTest **87 项 0 FAIL / ALL PASS**（回归无退化）。
⚠ 恢复逻辑依赖 pylon 真机会话，**离线测试覆盖不到，未伪报通过**。
现场三步：①重启软件点【打开相机】（会下发 5000）→ ②再跑一次「②自动曝光扫描」
→ ③看日志 `[扫描] 扫描结束，曝光已恢复...` + `[诊断②] 曝光已恢复为配置值 5000us`，
  关软件开 pylon 确认 5000.0。

## 5. 视野诊断假阳性：局部视野被当成整盘（已加三道硬闸）

### 现场事实
用户贴图纸并说明：**相机现在对着图中右上角（约 1:30）那 1 个双环孔**，局部视野，
画面中心有 550px 红光漫射亮斑，**没有完整 Ø34.2 外环**。
但「③视野诊断」输出：`R=305.0px / mm/px=0.056066 / 视野 107.6×67.3mm /
✅ 基准孔在视野内余量 19.19mm，datumHoles 方案可行 / ✅ 环带检出 9 个显著特征，方案可用`。

### 判定：整份输出作废（假阳性比不给结论更危险）
1. `mm/px 0.056066` vs 标定 `VisionPixelSizeMm=0.0234` → **2.4 倍**，机械/镜头/ROI 未变不可能
2. 拟合残差 `48.2/305=15.8%`（真圆 <5%）。`MeasureOuterRingRadius` 离群阈值
   `Math.Max(30, 3*std)` 在 std 大时放宽到 145px，等于不剔除，伪峰全进中位数
3. `MeasureDatumVisibility` 旧判据 `ringStd>=12 && peaks>=4`，`CountPeaks` 数的是
   能量曲线低于均值的连续段 → 辉光边缘/噪声凑出 9 段；而 8 个双环孔最多 8 个且等角 45°
4. `Result.DatumVisible` 默认 **true**，副标尺分支没检测却默认宣称"可见"

### 修复
- `FieldDiagnosis.Analyze` 加可选参数 `expectedMmPerPx`，`MainForm` 传 `_cfg.VisionPixelSizeMm`；
  偏差 >±25% 或拟合残差 >5% → `Success=false` + 「【诊断作废】标尺不可信」，
  明确写"当前很可能只对着 1 个双环孔，本工具不适用，改走 1 孔 + 转台分度"
- `CountPeaks` → `FindPeakAngles`（返回峰中心角度）+ `HasNominalSpacing`：
  要求峰数 2~8 且相邻间隔符合 45° 整数倍（容差 12°、命中率 ≥60%）
- `DatumVisible` 默认改 false、副标尺显式传 false；诊断失败时 UI 弹窗「本帧结论作废」
- 全库清理「换白光」误导文案（用户 11-06 已确认白光全黑、疑似红色窄带滤光片）：
  `PositioningStrategies.cs` 4 处、`PositioningStrategySelector.cs`、`MainForm.cs` 2 处、config 注释
