## 1. DWG 解析（aspose-cad 26.7）
- 源文件：`sourcedoc\P26009G打孔图纸（2026.11.2）.dwg`（473KB，AC1018/AutoCAD 2004）
- 读取需先复制到可写路径（`dwg_work\p.dwg` + `chmod +w`），原文件只读会 UnauthorizedAccessException
- **API 要点**：`cad.Image.load()` 返回基类 `aspose.cad.Image`，必须 `CadImage._cast_to(img).item` 才拿到真对象
- 实体类在 `aspose.cad.fileformats.cad.cadobjects`（不是 `.cad` 顶层）
- 坑：`e.type_name` 是枚举，取名要用 `e.type_name.name`（`str()` 拿不到名字）
- 坑：`CadCircle.center_point` / `CadText.default_value` / `CadMText.insertion_point`（不是 placement_point）
- 坑：`blocks_tables` 是块名表，真正实体在 `ci.block_entities.values`（CadBlockEntity，有 `.entities`）
- 图纸单位 1 = 0.01 mm；表盘中心 (20336.447, -248726.009)

## 4. 关键发现：角向基准有 90° 歧义
- 8 个自带双环孔名义角 = 30/60/120/150/210/240/300/330 → **90° 周期** → 单张图只有 4 个等效转角
- 之前 SmokeTest 报的"角度误差 88.96°"就是这个歧义，不是算法 bug
- 解决：新增 `VisionOptions.CoarseAlignDeg`（人工装夹粗对齐角），界面加"粗对齐角°"输入框
- 视觉侧返回 `PartPose.AngleCandidatesDeg`（全部候选），未给粗对齐角时**拒绝定位**而不是瞎猜

## 5. datumHoles 视觉算法（新增，替代 offsetCircle）
- 环带 r∈[0.70R, 0.96R]，按 `DatumHoleRadiusMm`(14.45) 收窄到 ±12%
- 双极性暗斑检测 → 面积/圆度/渠口扇区过滤
- **角度投票**：每个检出孔 × 每个名义角 → 候选转角投进 1° 直方图 → 3° 环形平滑 → 找全部局部极大（等价候选）
- 逐峰 ±4° 精扫，**主键=匹配孔数**（不是残差！残差按匹配孔归一化后，匹配少的假解残差会虚假地更小）
- 候选只保留"匹配孔数与最优相同"的解

### 第 4 点的技术判断（本轮核心）
"视野像显微镜 + 只有中心孔可见 + 基准孔在 R14.45mm" 三件事叠加，
意味着 **8 个基准孔可能根本不在画面内** → datumHoles 方案可能直接失效。
必须在办公室之外实测，必须分清三个独立问题，不能混着猜：
1. 相机允许的曝光/增益真实上限是多少？（是不是被 UI 或驱动卡住）
2. 当前照明到底需要多长曝光才够亮？（不够 → 换光源，不是调参数）
3. 视野有多大 → 基准孔在不在画面内？（不在 → 改硬件方案或改人工对刀）

### 本轮为此新增的工具
- `Hummingbird.Vision/FieldDiagnosis.cs`（新）
  - 用中央孔（已知 Ø2.9 沉孔 / Ø2.5 通孔）亮环反算 mm/px 与视野，判定基准孔是否在视野内。
  - **取保守假设**：用较小标称 Ø2.5 反算（视野更小）→ 宁可多报一次"不在视野内"，不漏掉硬件问题。
  - 候选圆筛选：直径 10px ~ 短边 60%，按"离画面中心距离分档（10px 一档）+ 同档取更小圆"排序，
    避免选中同心但巨大的白色外环（Ø34.2mm）导致 mm/px 算错。
- `Hummingbird.Core/Abstractions/ICameraDiagnostics.cs`（新，可选实现接口）
  - `GetParameterRanges()` / `ScanExposureAsync()`；**不放进 ICameraService 主接口**（主接口=加工必需能力，诊断是排查用，模拟相机可不实现）。
- `BaslerCameraService` 实现 `ICameraDiagnostics`：
  - `GetParameterRanges()`：读 ExposureMode/ExposureTime/Gain/BlackLevel/Gamma/PixelFormat/BinningH+V/Width/Height/SensorW/H。
  - `ScanExposureAsync()`：纯 C# 统计灰度（**相机工程刻意不引入 OpenCV 依赖**）。
- `MainForm.cs`「设备调试」页新增「现场诊断」分组：
  - ①相机参数范围 ②自动曝光扫描 ③视野诊断(mm/px) ④保存诊断结果（写 output/诊断_*.txt）
  - 曝光扫描判据：峰值灰度 ≥100 且均值 ≥20 视为可用；全档不达标 → 明确输出"是照明光强不足，不是曝光设置问题"。

### pylon 7.5 API 坑（踩过，别再踩）
- `PLCamera.Offset` 不存在 → 是 `PLCamera.BlackLevel`
- `PLCamera.Binning` 不存在 → 是 `PLCamera.BinningHorizontal` / `PLCamera.BinningVertical`
- 参数取值不是 `.Value/.Min/.Max` → 是 `GetValue() / GetMinimum() / GetMaximum()`
- `IFloatParameter` / `IIntegerParameter` 上都没有 `.Value/.Min/.Max` 属性（编译期直接报错）

## 12. 待现场执行（下次到客户现场按顺序做）
1. 打开相机 → 「①相机参数范围」→ 看曝光/增益真实上限（确认是否被卡住）
2. 「②自动曝光扫描」→ 找到当前照明够亮的最低曝光档
   - 若全档都暗 → 结论是照明光强不足，需加装高功率同轴/环形照明或换白光 LED
3. 「③视野诊断」→ 看 mm/px 与视野，判定 8 个基准孔在不在画面内
   - 若"不在视野内" → datumHoles 方案失效，退路：加大视野（短焦/中继镜/降 Binning）、
     或移动相机使中心孔与基准孔同时可见、或改纯人工对刀（粗对齐角需准到 ±0.5°）
4. 把 mm/px 实测值回填 `config.json` 的 `VisionPixelSizeMm`（当前仍是 0.02 占位值）
