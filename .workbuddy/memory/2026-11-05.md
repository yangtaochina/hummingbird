## 1. DWG 解析（aspose-cad 26.7）
- 源文件：`sourcedoc\P26009G打孔图纸（2026.11.2）.dwg`（473KB，AC1018/AutoCAD 2004）
- 读取需先复制到可写路径（`dwg_work\p.dwg` + `chmod +w`），原文件只读会 UnauthorizedAccessException
- **API 要点**：`cad.Image.load()` 返回基类 `aspose.cad.Image`，必须 `CadImage._cast_to(img).item` 才拿到真对象
- 实体类在 `aspose.cad.fileformats.cad.cadobjects`（不是 `.cad` 顶层）
- 坑：`e.type_name` 是枚举，取名要用 `e.type_name.name`（`str()` 拿不到名字）
- 坑：`CadCircle.center_point` / `CadText.default_value` / `CadMText.insertion_point`（不是 placement_point）
- 坑：`blocks_tables` 是块名表，真正实体在 `ci.block_entities.values`（CadBlockEntity，有 `.entities`）
- 图纸单位 1 = 0.01 mm；表盘中心 (20336.447, -248726.009)

## 4. 关键发现：角向基准有 90° 歧义
- 8 个自带双环孔名义角 = 30/60/120/150/210/240/300/330 → **90° 周期** → 单张图只有 4 个等效转角
- 之前 SmokeTest 报的"角度误差 88.96°"就是这个歧义，不是算法 bug
- 解决：新增 `VisionOptions.CoarseAlignDeg`（人工装夹粗对齐角），界面加"粗对齐角°"输入框
- 视觉侧返回 `PartPose.AngleCandidatesDeg`（全部候选），未给粗对齐角时**拒绝定位**而不是瞎猜

## 5. datumHoles 视觉算法（新增，替代 offsetCircle）
- 环带 r∈[0.70R, 0.96R]，按 `DatumHoleRadiusMm`(14.45) 收窄到 ±12%
- 双极性暗斑检测 → 面积/圆度/渠口扇区过滤
- **角度投票**：每个检出孔 × 每个名义角 → 候选转角投进 1° 直方图 → 3° 环形平滑 → 找全部局部极大（等价候选）
- 逐峰 ±4° 精扫，**主键=匹配孔数**（不是残差！残差按匹配孔归一化后，匹配少的假解残差会虚假地更小）
- 候选只保留"匹配孔数与最优相同"的解

"视野像显微镜 + 只有中心孔可见 + 基准孔在 R14.45mm" 三件事叠加，
意味着 **8 个基准孔可能根本不在画面内** → datumHoles 方案可能直接失效。

1. 相机允许的曝光/增益真实上限是多少？（是不是被 UI 或驱动卡住）

3. 视野有多大 → 基准孔在不在画面内？（不在 → 改硬件方案或改人工对刀）

## 13. 现场真机测试结果分析（2026-11-05 下午续）

### 用户回传的三步诊断结果
1. 相机参数范围：曝光 19~10000000us、增益 0~48、黑电平 0~1023.75、gamma 0~4、
   Mono8、Binning H/V 1~4、ROI 1920×1200（最大 1936×1216）、传感器 1936×1216um
2. 曝光扫描：100us→均值0.7 / 500us→6.3 / 1000us→13.2 / 5000us→63.2（可用）
   / 20000us→202.3（临界过曝）/ 50000us 起全白 255
3. 视野诊断失败：**"中心区未找到中央孔亮环，中心区均值255，全图最亮255"**

### 结论（关键）
- **第3步失败不是照明问题，是曝光停在 1000000μs 导致画面全白饱和**（均值=峰值=255）。
  判据必须先做"整体过曝检测"（均值>245 且标准差<8）再谈找特征。
- 中央孔在红光照明下**不可见**；画面中心的圆是**灯光反射的漫射辉光**（~220px），不是孔。
- 白色压圈外环 Ø34.2mm 是唯一可靠标尺。

### 真图离线定量分析（Image__2026-11-05__14-04-13.bmp，曝光 3114us）
- 白色外环半径实测 R≈691px（多方位角径向峰值法）→ **mm/px = 17.1/691 ≈ 0.0247**
- 视野 ≈ **47.5 × 29.7mm**（垂直半高 600px = 14.85mm）
- 角向基准孔 R14.45mm = 584~594px，**垂直余量仅 0.14~0.40mm（6~16px）** → 极端边缘状态
- 工件外径 Ø34.2mm 垂直方向放不下（视野高 29.7 < 34.2）
- 物理自洽：传感器像素 0.16mm，测得 0.0247mm/px → 缩小约 6.58×，与 25/35/50mm 镜头物距吻合
- **硬件建议：相机旋转 90° 竖装**（1920px 成为竖直方向，竖直半高 960px = 23.35mm，余量 +8.9mm）

### 代码改动
- `FieldDiagnosis.cs` **完全重写**：主标尺 中央孔 → 白色外环 Ø34.2mm；
  新增整体过曝检测、垂直方向余量判据（不能用水平半宽）、漫射亮斑识别、
  中央孔误检尺寸自检（偏差 >1.6× 判为误检）
- 修复 `At<float>()` 读 `CV_8UC1` 的严重 bug → 改 `At<byte>()`（曾读出 -5.7e26 垃圾值）
- 修复亮带平台取内边缘偏差 → 沿亮带扩展到峰值一半以下取中心
- `MainForm.cs` 曝光扫描判据改用均值 40~200 为可用区间，并识别"低档太暗+高档过曝"的动态范围跳空
- `config.json` 回填：`VisionPixelSizeMm` 0.02 → **0.0247**；`CameraExposureUs` 0 → **5000**
- SmokeTest 第 6 组重写为 5 类场景（A量到/B超视野/C全黑/D全白/E真机图离线复现），ALL PASS

### 经验教训（写代码务必记住）
- `CV_8UC1` 的 Mat **必须**用 `At<byte>()`，`At<float>()` 会把字节重解释为 float，读出垃圾值
- 径向峰值法测外环优于霍夫圆/整体轮廓拟合（真图外环只露几段弧，霍夫会拟合出偏心大圆）
- 亮带是平台，必须取**亮带中心**，不能取第一个亮点
- 判据要用**垂直方向**（图幅 1920×1200 横图，垂直半高 600px 才是限制）

## 15. 深度复核真机图 —— 推翻了一个关键结论（重要）

### 复查方法：极坐标展开（决定性）
把相机图按 (角度, 半径) 展开成 1440×340 的带状图
（横轴=0~360°，纵轴=R480~820px），横向条纹 = 周期性特征。

### 结论（决定性）
| 半径 | 位置 | 灰度标准差 | 判读 |
|---|---|---|---|
| R609px | 基准孔环带 | **4.9** | 全黑，**看不到任何周期性结构** |
| R660px | 基准孔环带 | 5.8 | 同上 |
| R720px | 外环亮弧 | **54.5** | 强信号 |
| R780px | 外环外侧 | 11.0 | 弱 |

⇒ **8 个双环基准孔在红光下完全不可见。**
   "基准孔在视野内"是**假象** —— 在视野内 ≠ 看得见。

### 其它修正（推翻上一轮的说法）
1. **上一轮说"相机旋转 90° 竖装可把竖直余量增到 8.9mm"是错的**。
   旋转只换画面方向，物理短边仍是 29.7mm，**对余量零增益**。
   真正约束是：**视野短边 29.7mm < 工件 Ø34.2mm**，工件根本放不下。
   正确解法：加大视野（短焦/拉远物距，短边 ≥36mm）或做机械限位。
2. **工件外径确认为 Ø34.2mm**（DWG r=1710 units，单位 0.01mm），
   另有 Ø33.2mm 内圈（r=1660）。DWG 中心孔 Ø2.9 / Ø2.3。
3. **亮弧圆心不在画面中心**：Kasa 拟合 center=(935,591)、R≈720px，
   相对画面中心 (960,600) 偏移约 (−25,−9)px。之前按画面中心算的 mm/px 有偏差。
4. 阈值敏感性：th=180/200/215 → R=732/730/720px，mm/px=0.0233~0.0237，
   垂直半高 14.0~14.2mm（**仍 < 14.45mm → 基准孔其实出画**）。
   th=235/245 → R=615/608px（拟合到了错误的更小的弧）。
   ⇒ 真实 R 在 720~733px，mm/px≈0.0234，**垂直半高仅 14.0mm**。

## 16. 客户新方案：单标记孔 + 夹具锁心，落地为策略模式

### 客户提议
"看到中心的小孔不好处理，让相机视野看**一个孔**（客户自己放上去），
其余 18 个孔我们看能否计算出来。写成策略模式，界面上判断调用哪个策略。"
配图为孔位 18 组加工图，红箭头指向右上方一个蓝色双环孔（R14.45，30° 均布之一）。

### 数学判定（关键，别搞错）
- 平面刚体变换 = 3 个自由度：中心 X、中心 Y、转角 θ
- 一个孔的孔心只给 2 个约束（像素 x,y）→ **欠定，解不出**
- 必须由**夹具定位销/止口锁死中心**（2 个自由度交机械），视觉只求转角 θ
- 此时：θ = ClockAngle(孔心 − 夹具中心) − 标记孔名义时钟角
- 18 孔 = DWG 模板坐标按 θ 旋转 + 夹具中心（经标定换算到机床系）—— 原 ComputeTargets 已支持，零改动
- ⚠ 标记孔**必须随工件转动**；固定在夹具上则转角永远测不出（Check 会拒绝）
- ⚠ 中心精度从此取决于**夹具重复定位精度**，不再由视觉实时修正

### 为什么这方案明显更好弄
1. 视野缩到只拍一个孔 → 放大倍数高、孔看得清、红光反射问题局部化
2. 绕开「视野短边 28.1mm < 工件 Ø34.2mm」死结
3. 绕开「8 个基准孔在红光下完全不可见」
4. 相比改镜头/改照明/双相机，成本最低

### 实现（策略模式）
- `Core/Abstractions/IPositioningStrategy.cs`（新）
  - `StrategyIds`：fullFieldDatumHoles / singleFiducial / manualFixture
  - `StrategyContext`（8 个现场硬前提）+ `StrategyReadiness`（OK/WARN/BLOCK）
  - `IPositioningStrategy : IVisionService` + Id/DisplayName/Description/Prerequisites/Check()
- `Core/Workflow/PositioningStrategySelector.cs`（新）
  - Recommend 按工程优先级：整盘 > 单标记孔 > 纯机械对刀
  - DescribeAll 输出每个策略的缺口清单（界面自检）
- `Vision/PositioningStrategies.cs`（新，3 个策略）
  - ① `FullFieldDatumHolesStrategy`：包装现有 DialPositioning，旧代码零改动
  - ② `SingleFiducialStrategy`：Otsu+轮廓+圆度找唯一孔（亮孔/暗孔两种极性都试）
    → 方位角求转角 → **孔心到中心距离校验**（超差拒绝出坐标，防打废工件）
    → 中心取夹具锁定像素（允许不在画面内，只参与坐标换算）
  - ③ `ManualFixtureStrategy`：纯机械对刀兜底，置信度故意压到 0.30
