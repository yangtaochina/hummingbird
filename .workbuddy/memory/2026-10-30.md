## 重大突破：搞清了机床真实架构，BadTimeout 真因（16:05）
- **828D PU 272.5 是"分体式"变体**（查西门子 PPU.5 迁移指南确认）：PU（NC 单元，X120=192.168.214.1 / X127=192.168.215.1 / X130=192.168.100.10）+ **PCU/IPC（Windows 工控机跑 Operate，X2 系统网=192.168.214.241，X1 公司网=0.0.0.0 未配置！）**+ 独立显示屏。用户之前网络一览照片里"PU/PCU"两段与此完全对上。
- **OPC UA 服务器跑在 Windows IPC（PCU）上**，不在 PU 上 → 笔记本插 PU 的 X130(192.168.100.10) 永远连不上；IPC 的公司网口 X1 没配 IP(0.0.0.0)，所以 OPC UA 设置页"公司网络"显示 127.0.0.1（自动探测值，不可手输——这就是用户"设置不了"的原因，页面本身没坏）
- **修复路径（正式）**：调试→网络→「公司网络」软键→给 PCU 的 X1 配静态 IP 192.168.100.20/24→「保存PCU设置」→重启生效→OPC UA 页公司网络自动变 192.168.100.20→网线插 IPC 机箱上的 X1 口（电柜里，问现场电气工程师）→UaExpert 连 opc.tcp://192.168.100.20:4840
- **快速验证（备选）**：笔记本插电柜内系统网交换机空余口，IP 设 192.168.214.200/24（先 ping 确认没人用），直连 opc.tcp://192.168.214.241:4840（状态页已绿勾）——只做短暂测试，勿长期接系统网
- PCU X1 口识别技巧：网络一览 PCU 段 X1 MAC=30:2F:1E:7D:E4:6B；插线后看 X1 是否变"已连接"
- 对项目影响：**我们 App 的 config 里 CNC OPC UA 地址应指向 IPC X1（192.168.100.20），不是 PU X130**；OpcUaCncService 无需改，只改配置
- 屏幕报警 3008（文字未读出）+ 之前 3000急停/700020 均为机床自身状态，与通讯无关
